<a id="summary"></a>
## Summary

Training Panel 3.7.0 brings the authenticated, team-scoped Child to the Mother 3.6.4 interaction standard while preserving a strict remote-safe boundary. It adds responsive persistent navigation, route-aware training, team Physics presets, all-runs History, bounded insights, safe deployment evidence, detection visibility, activity attribution, and compatibility-aware Connection controls.

<a id="changes"></a>
## Changes

- Child uses a buildless ES-module shell with desktop sidebar, four-item mobile navigation, URL-backed views and selection, saved filters and drafts, accessible feedback, and layouts tested at 390 px, 768 px, and desktop width.
- Train supports Standard, F1, F2, F3, and full-pipeline routes with Native springs, checkpoint references, safe defaults, preset selection, idempotent requests, and omission of irrelevant fields.
- Shared Reward, Terrain, and Physics presets are role-gated. History adds folders, bulk movement, admin-only deletion, comparison, progress, bounded curves, provenance, checkpoint evolution, and remote-safe run actions.
- The worker resolves authoritative roles and contained checkpoints, publishes capabilities and read-only detection settings, projects redacted activity and bounded run evidence, and separates Isaac GPU work from Drive, existing-ONNX validation, and MuJoCo-only work.
- Remote Deploy supports repository-owned models and enumerated scenarios for ONNX validation, export-and-validate, MuJoCo smoke, MP4 recording, and an optional ROS mock. It never accepts arbitrary host paths, shell fragments, GUI viewer requests, or hardware actuation.

<a id="security-and-compatibility"></a>
## Security and compatibility

Apply `supabase/migrations/20260814_370_remote_parity.sql` after the 3.4.10 base schema. The additive migration preserves existing rows and adds machine capabilities, Physics presets, request idempotency, bounded run projections, activity source identity, authoritative job attribution, mutation audit triggers, constrained metadata updates, and requester/admin queued cancellation. A Child connected to an older schema or worker remains signed in and read-only until both protocol versions report `3.7.0-remote-parity`.

Viewer is inspection-only. Operator may edit metadata, presets, and folders and submit non-destructive jobs. Admin additionally performs single and bulk deletion. Terminal access, raw logs, worker administration, host file operations, convergence-setting edits, GUI viewers, and physical deployment remain Mother-only.

<a id="rollout-and-rollback"></a>
## Rollout and rollback

Pause remote acceptance, apply the migration, update Mother, restart the worker, verify the capability row, heartbeat, role policies, and schema check, publish Child assets, then resume acceptance. If order differs, Child stays read-only. To roll back, pause acceptance and restore the prior Child and worker assets; leave additive database objects in place because older clients ignore them.
