<a id="release"></a>
## 版本

Training Panel 3.6.1 防止已知的 Explicit 扭轉彈簧數值 runaway 進入新 policy training，同時保留兩種彈簧實作與歷史 run identity。

<a id="spring-safety"></a>
## 彈簧安全邊界

- 新 policy run 暫時預設使用 Native。
- Explicit 在 Train 中會顯示但無法選擇，CLI/API/process guards 會在寫入 history、啟動 simulator 或 spawn process 前拒絕 policy training。
- Explicit 仍可用於決定性 spring-release characterization；Native 仍未校準，也未被選為 production。
- 完整 Sensor V2 pipeline 會在 F1、F2 與 F3 中原樣傳遞已選 backend。

<a id="provenance"></a>
## Checkpoint provenance

已 stamp 的 uncalibrated checkpoints 現在會拒絕 backend mismatch。沒有 metadata 的現有 run 保留歷史 Explicit fallback，不會被靜默重新標記。Play、video 與 export 繼續解析 run 已記錄的 backend。

<a id="physics-editor"></a>
## Physics editor 修正

扭轉彈簧 editor 現在與 runtime defaults 一致：damping 為零，actuator-path effort/velocity limits 為 nonbinding，並保留穩定的 `damper_0` 到 `damper_5` aliases。Labels 會區分 legacy uniform compatibility values 與 per-spring parameters，並提醒 armature 需要實體證據。

<a id="upgrade"></a>
## 升級說明

Restart 本機 Mother，並載入 `3.6.1-spring-safety` assets。若已啟用 remote operation，先 pause job acceptance，再從 Control Center 明確 restart remote worker；只 restart Mother 不會替換已在執行的 worker，而新的 worker 會為省略此欄位的現有 `3.4.10-sync-health` Child request 補上 Native default。重新接受 job 前，先確認新的 worker heartbeat。現有 Explicit checkpoints 不會被轉換為 Native。此 release 不改變獨立 version 的 remote Child/worker protocol，也不會選出可部署的 spring backend。
