## 版本與日期

- 版本：`3.7.0-remote-parity`
- 日期：2026-08-14

<a id="summary"></a>
## 摘要

Training Panel 3.7.0 讓具 authentication、team scope 的 Child 達到 Mother 3.6.4 interaction standard，同時維持嚴格的 remote-safe boundary。它新增 responsive persistent navigation、route-aware training、團隊 Physics preset、all-runs History、bounded insight、安全 deployment evidence、detection visibility、activity attribution 與 compatibility-aware Connection controls。

<a id="changes"></a>
## 變更

- Child 使用 buildless ES-module shell，包含 desktop sidebar、四項 mobile navigation、URL-backed view/selection、保留的 filter/draft、accessible feedback，以及在 390 px、768 px 與 desktop width 測試的 layout。
- Train 支援 Standard、F1、F2、F3 與 full-pipeline route，使用 Native spring、checkpoint reference、安全 default、preset selection、idempotent request，並省略無關欄位。
- 共享 Reward、Terrain 與 Physics preset 受 role gate 保護。History 新增 folder、bulk move、admin-only deletion、comparison、progress、bounded curve、provenance、checkpoint evolution 與 remote-safe run action。
- Worker 解析 authoritative role 與 containment-checked checkpoint、發布 capability 與 read-only detection setting、投影 redacted activity 與 bounded run evidence，並把 Isaac GPU 工作與 Drive、既有 ONNX validation 及 MuJoCo-only 工作分開。
- Remote Deploy 只使用 repository-owned model 與列舉 scenario，支援 ONNX validation、export-and-validate、MuJoCo smoke、MP4 recording 與 optional ROS mock；絕不接受任意 host path、shell fragment、GUI viewer request 或 hardware actuation。

<a id="security-and-compatibility"></a>
## 安全與相容性

在 3.4.10 base schema 後套用 `supabase/migrations/20260814_370_remote_parity.sql`。Additive migration 保留既有 row，並新增 machine capability、Physics preset、request idempotency、bounded run projection、activity source identity、authoritative job attribution、mutation audit trigger、受限 metadata update 與 requester/admin queued cancellation。Child 連到舊 schema 或 worker 時仍可登入及檢視，直到兩個 protocol version 都回報 `3.7.0-remote-parity` 前維持 read-only。

Viewer 僅能檢視。Operator 可編輯 metadata、preset 與 folder，並送出 non-destructive job。Admin 另可執行 single/bulk deletion。Terminal access、raw log、worker administration、host file operation、convergence-setting edit、GUI viewer 與 physical deployment 仍僅限 Mother。

<a id="rollout-and-rollback"></a>
## Rollout 與 rollback

Pause remote acceptance、套用 migration、更新 Mother、restart worker、驗證 capability row、heartbeat、role policy 與 schema check、發布 Child asset，之後才恢復 acceptance。若順序不同，Child 保持 read-only。Rollback 時 pause acceptance 並還原先前 Child/worker asset；保留 additive database object，因為舊 client 會忽略它們。

<a id="verification-and-evidence"></a>
## 驗證與證據

Repository evidence 包含 Node contract test、Python worker/schema test、涵蓋各 role 與目標 width 的 mocked Child Playwright suite、完整 Mother Playwright suite、Training Panel Python suite、documentation validation/unit test 與 `git diff --check`。外部 staging Supabase smoke 仍是 operator rollout gate，由 active implementation plan 追蹤；本 release record 不會宣稱 repository workspace 無法取得的 deployment evidence。
