<a id="release"></a>
## Release

Training Panel 3.4.10 is the consolidated release represented by the current Python version, mother UI, child assets, heartbeat, and worker schema. This record continues from the evidenced 3.4.3 history; it does not fabricate separate releases 3.4.4 through 3.4.9.

<a id="sync"></a>
## Sync and history

- Machine-scoped child queries and explicit clearing keep runs, jobs, artifacts, names, notes, and folders aligned.
- Folder and run deletion tombstones prevent stale Supabase rows from recreating deleted local state.
- Active reward/terrain selection and per-run override snapshots remain distinguishable; manual training no longer consumes stale panel files without `--panel_overrides`.
- History persistence uses locking and atomic replacement.

<a id="operations"></a>
## Operations

- The mother queue serializes training, playback, video, and ONNX export and exposes queue/GPU-lock state remotely.
- Terrain presets and saved run terrain are applied consistently to training and faithful playback/video.
- Worker heartbeat and UI version surfaces use `3.4.10-sync-health`.

<a id="deployment"></a>
## Deployment

- The Deploy page adds export integrity, ONNX/runtime, Torch parity, policy-contract, safety-fault, optional ROS mock, and advisory MuJoCo stages.
- Deployment validation runs in the panel Python while Isaac actions stay in the Isaac environment.
- Contract parity aligns the ROS policy loop to 60 Hz and the current ABAD normalization/limits.

<a id="upgrade"></a>
## Upgrade notes

Pull the complete release, restart mother and worker together, and reapply `tools/training_panel/supabase/schema.sql` when the deployed schema predates the folder/sync additions. Clear browser caches only after confirming asset URLs carry the 3.4.10 cache key. Keep machine tokens private.
