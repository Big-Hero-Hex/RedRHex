<a id="summary"></a>
## Summary

Training Panel 3.8.0 adds an off-by-default, simulation-only Autopilot preview for durable bounded reward campaigns. A human drafts and arms the exact goal and budget; an external ChatGPT advisor may propose one allowlisted weight change; the panel remains authoritative for execution, evaluation, ranking, budgets, recovery, and success.

<a id="changes"></a>
## Changes

- Mother adds an Autopilot workspace for exact command preview, baseline and tunable selection, budget review, explicit arming, lifecycle and GPU/connector status, candidate lineage, evaluation gates, paired-seed evidence, campaign-owned stop controls, and patch export.
- SQLite WAL state, append-only events, revision/idempotency checks, SHA-256-addressed artifacts, restart reconciliation, immutable per-run profiles, exact checkpoint loading, and host GPU serialization support unattended local work without duplicate launches. Policy-only baselines are selected by recorded run, checkpoint iteration, and SHA-256. Campaign training records only the cap-bound final checkpoint receipt, including monitorless recovery, rather than using History's latest-file scan. Installed dependency files and editable Git source state are content-bound, and V1 rejects non-default terrain overrides.
- Advisor candidates are restricted to the finite 80/90/100/110/120% campaign-start reward lattice after human narrowing. Decision context exposes lattice availability, attempted moves, leader deltas, evidence IDs, and remaining budgets without raw logs or local paths.
- Standard PPO control and candidate trials are followed by exact-checkpoint command-sweep evaluation. The evidence identity binds the recorded evaluator environment count, 600 steps, the exact 1/60-second control interval, and derived duration; every command/environment must supply its full horizon, and command success durations must reconcile with episode ratios. Command, episode, summary, and evaluated-report artifacts are immutable and revalidated after restart and before confirmation, so missing, truncated, or tampered evidence fails closed. Deterministic hard gates and three-seed confirmation alone can produce `simulation_goal_met`.
- Controller failures persist a campaign-owned stop intent before signaling active work. A later tick or restart completes that stop, cumulative GPU accounting, and fail-closed terminal transition without abandoning the process identity.
- The `redrhex-autopilot` plugin supplies a narrow stdio/loopback Streamable HTTP MCP adapter and scheduled-advisor skill. It cannot arm, resume, widen budgets, run arbitrary commands, apply source changes, export or deploy policies, operate hardware, or stop unrelated work.
- Legacy Reward Agent JSON is retained and imported as non-armable references. The standalone Reward Agent workflow remains available but is not the Autopilot advisor or success authority.
- Mother Settings now presents Google account and video-folder choices separately. Operators can paste an accessible Google Drive folder URL or enter a My Drive path; folder IDs and optional legacy resource keys stay local, exports remain private, and **Change Google account** owns the reconnect workflow.

- The Physics page adds a robot preview built from the deploy URDF and served by `GET /api/physics/robot-geometry`. It mirrors the preset being edited rather than robot state: torsion-spring rest positions turn the matching leg, the center-of-mass marker tracks its offset fields, and contact friction tints the ground. Selecting a leg reuses the existing search filter, and quantities with no spatial depiction are reported as text. Rendering uses a vendored, pinned three.js served from `static/vendor/`, keeping the panel bundler-free and offline; without WebGL it degrades to an interactive top-down schematic. The preview reports that the right-side leg names in the field list do not match the URDF mount positions; canonical joint indices, actuator grouping, and tripod membership are unaffected.

<a id="compatibility-and-activation"></a>
## Compatibility and activation

Autopilot supports ForwardFast stage 1 and Direct stages 1–5 only; Sensor V2 is excluded. It is disabled unless Mother starts with `REDRHEX_AUTOPILOT_ENABLED=1`. Keep the panel and MCP adapter on loopback and keep bearer/tunnel credentials outside the repository.

This release does not change the Supabase schema or the Child/worker contract: `REMOTE_PROTOCOL_VERSION` remains `3.7.0-remote-parity`, and remote campaign control is not available. It does not provision ChatGPT Scheduled, an OpenAI Secure MCP Tunnel, Platform tunnel ID/permissions, or runtime credentials. Operators must configure those external services separately before expecting 15-minute unattended advisor visits; without them, active local work finishes and the campaign waits safely.

<a id="rollout-and-boundary"></a>
## Rollout and boundary

Keep the capability disabled until fake-advisor and restart tests pass in the target environment. Then progress through shadow proposals, a four-trial ForwardFast pilot, restart recovery, and a full opt-in qualification campaign before enabling Direct stages 2–5. The strongest terminal claim is `simulation_goal_met`; policy export, deployment readiness, hardware promotion, and robot actuation remain separate human-governed workflows.

<a id="verification-and-evidence"></a>
## Verification and evidence

Repository coverage exercises schemas, the finite reward lattice, exact baseline identities, default-terrain enforcement, state transitions, budgets, idempotency, deterministic gates and ranking, immutable-report tamper detection, controller failure-stop recovery, fake unattended process loops and recovery, HTTP/MCP scope, browser draft and lifecycle behavior, bilingual documentation, and existing Training Panel/Reward Agent behavior. Real Isaac and external Scheduled/tunnel pilots remain explicit rollout gates; this preview does not claim they were provisioned or completed by repository tests.
