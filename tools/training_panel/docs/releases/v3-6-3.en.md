<a id="release"></a>
## Release

Training Panel 3.6.3 repairs History run comparison, removes states where the interface reported work it had not performed, and makes the run list navigable by keyboard.

<a id="comparison"></a>
## Run comparison

Comparison now renders into its own panel instead of replacing the run details panel. Closing a comparison previously destroyed the details elements, so every later detail render failed and the History poll stopped refreshing until the page was reloaded. Comparison can be closed with `Escape`, the compared run is marked in the list, and selecting **Compare** on another run swaps the compared column.

<a id="destructive-actions"></a>
## Destructive actions

A run is marked as deleting only after the operator confirms; the card no longer greys itself out while the confirmation dialog is still open. Bulk deletion now requires a typed `DELETE` acknowledgement, so removing many runs is no longer easier than removing one. Folder creation, renaming, and removal use the panel confirmation dialog instead of browser dialogs.

<a id="run-list"></a>
## Run list and filters

- Search, status, sort, and folder selection persist across reloads, and a **Clear filters** control appears whenever a filter is hiding runs.
- The run count reads `N of M` while filtered.
- Search also matches folder name, note text, and preset ids.
- Sorting by status ranks running, stopping, and queued runs above finished ones instead of sorting alphabetically.
- `/` focuses search, `j`/`k` and the arrow keys move the selection, and `Escape` clears the search field.
- Checkbox selection supports shift-click ranges, and bulk move and delete controls appear only once runs are selected.
- Folder rows are keyboard-reachable buttons.
- The search and filter row stays in view while the run list scrolls.
- A running run card renders one progress bar; it previously rendered two.

<a id="run-details"></a>
## Run details and notifications

Unsaved notes are kept per run when the selection changes and are marked as an unsaved draft, and leaving the page with unsaved notes warns first. Relative timestamps carry the absolute time. A run that reaches a finished state raises a History notification, not only a newly created run.

<a id="upgrade"></a>
## Upgrade notes

Restart the local Mother and load the `3.6.3-history-clarity` assets. This local UI release does not change the independently versioned `3.4.10-sync-health` remote Child/worker protocol, Supabase schema, training commands, or existing run records.
