# Training Panel V3.5 — Training Insight & Reproducibility

**Date:** 2026-08-01
**Branch:** `feat/panel-3.5`
**Scope:** mother panel only (`tools/training_panel/training_panel/`, `tools/training_panel/static/`). The
`remote_web/` child ("RedRHex To Go") is explicitly out of scope.

## Problem

The panel launches, queues, tunes, and archives runs well, but it cannot answer three questions an
operator asks constantly:

1. **"When will this finish?"** A running job shows only `running` plus a log tail. There is no
   iteration count, no percentage, no ETA.
2. **"Is this run any good?"** Reward curves live only in TensorBoard behind a tunnel. The panel's
   only in-app metric artifact is a static PNG written after the run ends.
3. **"What exactly produced this checkpoint?"** Seed is an optional form field that is blank by
   default, and no code version is recorded. Two runs of the "same" config are not reproducible, and
   an old run cannot be tied to the code that produced it.

A fourth gap wastes hardware: a run that goes NaN or collapses keeps burning GPU hours until a human
notices. The existing `ConvergenceChecker` only detects the *healthy* plateau case.

## Non-goals

- Child/remote UI changes, Supabase schema changes, notification schema changes beyond reusing the
  existing convergence event path.
- Run-vs-run metric comparison, sortable metric columns, sweeps, auth, SSE, `app.js` module split.
  These remain on the backlog.

## Design

### 1. Progress and ETA (`training_panel/progress.py`, new)

`rsl_rl` already prints everything required once per iteration
(`rsl_rl/runners/on_policy_runner.py`, lines 239-288). The panel simply never read it. The block as
captured in panel process logs, ANSI escapes included:

```
 [1m Learning iteration 8/10 [0m
        Computation: 21453 steps/s (collection: 0.412s, learning 0.221s)
        Mean reward: 12.34
Mean episode length: 431.20
    Total timesteps: 491520
     Iteration time: 0.97s
                ETA: 00:00:01
```

**Interface.** One pure function, no I/O:

```python
def parse_progress(log_text: str) -> dict | None
```

Returns `None` when no complete iteration block is present, otherwise:

```python
{
    "iteration": 8, "total_iterations": 10, "percent": 80.0,
    "steps_per_second": 21453.0, "mean_reward": 12.34,
    "mean_episode_length": 431.2, "total_timesteps": 491520,
    "iteration_seconds": 0.97, "eta_seconds": 1,
}
```

Rules: strip ANSI CSI sequences first; scan backward and use the **last complete** block, so a
half-flushed tail never yields a truncated reading; every field is individually optional, because
`rsl_rl` omits the reward lines until its reward buffer fills.

**Wiring.** `ProcessManager._monitor_training` already runs a 2-second poll loop
(`processes.py:2012`). Add a 5-second-interval tail-and-parse of the run's process log using the
existing `tail_file` helper, writing one new history field:

```python
run["progress"] = {**parse_progress(...), "updated_at": "<iso8601>"}
```

A single dict field keeps history-record churn to one key. Parse failures are swallowed exactly like
the surrounding convergence block — the monitor thread must never die from a display feature.

**Frontend.** A progress bar plus `340/1000 · ETA 1:12:33 · 21k steps/s` on the history run card and
in run details. Rendered only when the run is running and `updated_at` is under 5 minutes old, so a
crashed run never shows a frozen bar as if it were live.

### 2. Seed and git provenance

**Seed.** `commands.py` currently appends `--seed` only when the field is non-empty
(`commands.py:154`). Change: when the field is empty the panel generates
`random.randint(0, 2**31 - 1)`, passes it explicitly, and records it in the run's params.

This is a deliberate behavior change. Previously a blank seed meant "whatever the training env
defaults to"; now it means "panel-chosen and recorded". Runs become reproducible, at the cost of no
longer inheriting the env default. An explicit seed typed by the user is passed through unchanged.

**Provenance.** New `training_panel/provenance.py`:

```python
def git_provenance(repo_root: Path) -> dict   # {"commit", "short", "branch", "dirty"} or {}
```

Implemented with `git rev-parse` / `git status --porcelain` subprocesses under a short timeout. Any
failure — no git, detached worktree, timeout — returns `{}`; the panel must work in a tarball
checkout. Captured once when the run record is created and stored under a `git` key. Run details
render `abc1234 (dirty)` with a copy button.

### 3. Live curves

**Backend.** `GET /api/runs/<id>/scalars?tags=<csv>&points=<n>` returns

```json
{"tags": {"Train/mean_reward": [[step, value], ...]}, "log_dir": "...", "truncated": false}
```

Data comes from `ConvergenceChecker.read_scalars`, which already enforces the 128 MB event-file and
2000-scalar caps. On top of that: uniform downsample to `points` (default 200, hard max 2000), a
tag allowlist so the parameter cannot be used to sweep arbitrary strings, and an in-process cache
keyed on `(log_dir, tag, event-file mtime+size)` so repeated polls of a finished run are free.

**Frontend.** A hand-rolled inline SVG sparkline — no charting dependency, no external asset, so the
panel keeps working offline and under any CSP. Placed in run details beneath the existing
TensorBoard summary image. Default tags `Train/mean_reward` and `Train/mean_episode_length`. Refresh
piggybacks the existing runs poll and only fires while the details panel is open, so a background
tab costs nothing.

### 4. Divergence guard

Extends `convergence.py` rather than adding a parallel system — it already reads the same scalars on
the same 60-second cycle.

New config fields: `divergence_enabled` (default `true`), `divergence_action`
(`"notify" | "stop"`, default `"notify"`), `divergence_patience_iterations` (default 100),
`divergence_collapse_pct` (default 40.0).

Detection, against the same `primary_tag`:

- **NaN/inf** in the most recent value — unambiguous, training is already dead.
- **Collapse** — the recent window's max has stayed below `divergence_collapse_pct` percent of the
  run's all-time max for at least `divergence_patience_iterations` iterations.

Action: mark the run `divergence_detected` with iteration and reason, surface it in panel status, and
send one Discord notification through the existing convergence notification path. Fires **once** per
run, guarded like the existing convergence flag.

**Auto-stop is opt-in.** Default is notify-only; a checkbox in the Convergence view switches the
action to `stop`, which calls the existing `ProcessManager.stop(run_id)`. A false positive must never
be able to kill a run the operator did not opt in to.

## Testing

Per item: new pytest module under `tools/training_panel/tests/`, written before the implementation.

- `test_progress.py` — fixture text lifted verbatim from a real captured log, including ANSI codes:
  full block, partial trailing block, reward lines absent, no block at all, malformed ETA.
- `test_provenance.py` — real `git init` in a tmp dir for clean and dirty cases; non-repo directory
  returns `{}`.
- `test_scalars_api.py` — downsampling arithmetic, tag allowlist rejection, cache hit on unchanged
  mtime, missing log dir.
- `test_divergence.py` — NaN series, collapse crossing and not crossing patience, healthy series
  (must not fire), fires only once.

The full suite (`python -m pytest tools/training_panel/tests -q`, baseline **268 passed, 41 subtests
passed**) runs after every item. No commit lands on red.
