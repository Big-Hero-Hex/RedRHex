# Training Panel V3.6 — Panel UX

**Date:** 2026-08-01
**Branch:** `feat/panel-3.6-ux` (off `feat/panel-3.5`)
**Scope:** mother panel frontend — `tools/training_panel/static/`. No Python behavior changes; `remote_web/` untouched.

## Problem

Six findings from a UX pass over the running panel. The first is a correctness bug, not polish.

1. **Errors from six of eight views are invisible.** All 75 `setStatus()` calls write to `#notes-status`
   (`index.html:393`), which lives inside the History details pane beneath the Notes box. Train has its
   own `#train-status`; Deploy has `#deploy-status`. Everything else — Rewards, Terrain, Convergence,
   Activity, Control Center, and every History action taken while another view is open — fails silently.
2. **View and selection are not addressable.** `setView` (`app.js:338`) only toggles CSS classes. No hash,
   no `pushState`; `localStorage` holds theme and notification state only. Refresh returns to Train with
   nothing selected, and a run cannot be linked to a teammate.
3. **Tooltips are hover-only.** `[data-tooltip]:hover::after` (`styles.css:1395`), 45 of them, several
   carrying operational meaning ("Triggers after 200 stable iterations at 2% threshold"). Unreachable by
   keyboard or touch.
4. **Run cards carry up to nine buttons each**, always (`app.js:1050-1067`), across 57 runs.
5. **Loading is indistinguishable from empty.** Switching to Deploy or Activity before the fetch lands
   shows "No deploy readiness report for this run yet" — which also means "there genuinely is none".
6. **No freshness signal.** Polling is 10s active / 30s idle with no last-updated stamp and no failure
   indication. Data can be 30s stale, or arbitrarily stale after a failed poll, with nothing on screen.

## Non-goals

Broader accessibility work (the document has zero `role=` attributes and the sidebar is not a tablist),
keyboard shortcuts, the `app.js` module split, and anything in `remote_web/`. Items 7 and 8 from the UX
pass stay on the backlog.

## Visual direction

The brief pins the direction: this must read as the same instrument. `styles.css` already defines a
complete token system — a desaturated blue-green industrial palette with paired semantic colors
(`--red`/`--red-dark`, `--green`/`--green-bg`, `--blue`/`--blue-bg`, `--amber`/`--amber-bg`), a full dark
theme, `--shadow`, and `--focus-ring`. Every new component derives from those tokens. No new palette, no
new typeface, no hardcoded color.

The one new expressive element is the **freshness dot**: a small live indicator in the topbar that makes
the panel feel like an instrument reading a live system rather than a page you refresh. Everything else
added here is deliberately quiet — the toast is a bordered surface, the menu is a plain popover, the
skeletons are a two-token shimmer. Spend the boldness in one place.

## Design

### 1. Global status region

New `#panel-status` region, fixed bottom-right, `aria-live="polite"`, holding up to three stacked toasts.

`setStatus(message, linkUrl)` keeps its exact signature and becomes the toast entry point, so all 75 call
sites are unchanged. A `tone` is inferred rather than threaded through every caller: messages arriving via
`handleActionError` are errors; everything else is info.

- info / success: auto-dismiss after 6s, `--blue` left border
- error: **no auto-dismiss**, `--red` left border, explicit close button — a failed action must not
  vanish before it is read
- duplicate consecutive messages collapse with a counter rather than stacking

`#notes-status` stays in the markup as the notes-local line, since notes saving is the one place an
inline confirmation beside the control is right. It is no longer the destination for unrelated views.

### 2. URL routing

Hash routing, since the panel is served from a static handler with no history-API fallback:

- `#/train`, `#/rewards`, `#/terrain`, `#/history`, `#/deploy`, `#/convergence`, `#/activity`, `#/access`
- `#/history/<runId>` when a run is selected

`setView` and `selectRun` write the hash; a `hashchange` listener applies it, guarded by a
"currently applying" flag so programmatic writes do not re-enter. On load, an unknown or malformed hash
falls back to `#/train` rather than erroring, and a `runId` that no longer exists selects nothing and
shows the History view rather than a toast on every reload.

### 3. Tooltips reachable by keyboard

Add `:focus-visible` to the existing `:hover::after` rule. CSS-only, no JS, no markup change. Touch is
explicitly out of scope — a `::after` tooltip cannot be made touch-accessible without rebuilding the
component, and the operational content is duplicated in the manual.

### 4. Run card overflow menu

Primary, always visible: **TensorBoard**, **Play**, **Console**.
Conditional and always visible when applicable: **Stop Training**, **Stop Recording**, **Cancel Queue** —
a stop control is never hidden behind a menu.
In the `⋮` menu: **Resume to Train**, **Tweak**, **Compare**.

The menu is a popover anchored to its button: `aria-haspopup="menu"`, `aria-expanded`, `role="menu"` with
`role="menuitem"` children. Enter/Space opens, Escape closes and returns focus to the trigger, arrow keys
move between items, a click elsewhere closes it. Only one menu open at a time. The menu must survive the
runs poll re-rendering the list: the open menu's run id lives in `state`, and re-render restores it.

### 5. Loading states

A `state.loading` set keyed by resource (`runs`, `deploy`, `activity`, `rewards`, `terrain`). Panels render
a skeleton while their key is present and the current data is empty — a background refresh of already-shown
data must not flash skeletons over it. Skeleton is a shimmer between `--surface-2` and `--surface-hover`,
respecting `prefers-reduced-motion` by falling back to a static block.

Empty-state copy stays as the invitation it should be; loading copy is distinct and never claims emptiness.

### 6. Freshness indicator

In the topbar beside Refresh: a dot plus a relative label.

- **live** (`--green`): last poll succeeded within 1.5× the current poll interval
- **stale** (`--amber`): last success is older than that — the panel is idle-polling or a poll was slow
- **failed** (`--red`): the last poll threw; the label names the failure

The label re-renders on a 5s tick — text only, no data fetch. `title` and tooltip carry the exact
timestamp. This is the component that answers "is this thing actually connected", which is precisely the
question the current panel cannot answer, and it is the reason the fetch failure earlier today was
ambiguous.

## Testing

Playwright against real Chrome, which works in this environment: `/usr/bin/google-chrome`, and
`python -m pytest tools/training_panel/ui_tests -q` currently passes 7 tests. This is a UI change set, so
UI tests are the verification, not reasoning:

- a status toast appears for a failed action taken from a non-History view, and error toasts persist
- the hash updates on view switch and run selection, and a deep link restores both on load
- an unknown hash and a dead run id both degrade to a sane view without throwing
- the overflow menu opens, closes on Escape with focus returned, and survives a runs poll re-render
- stop controls are never inside the menu
- a skeleton is visible before data arrives and is replaced, and a background refresh does not reflash it
- the freshness dot reports failed when the backend is stopped mid-session

The existing Python suite (321 passed, 41 subtests) must stay green; no Python is expected to change.
